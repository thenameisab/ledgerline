# Ledgerline

Ledgerline is a billing and revenue tool for businesses that sell API calls. It
loads daily API usage per account, prices it (flat, graduated tier, whole-volume
slab, and stitched bundles), compares revenue with vendor cost, flags unpriced
usage, and produces invoices with PDF and CSV export. It also has manual
entries, vendor reconciliation, usage alerts, aliases for unmapped names,
sandbox rules, three roles (admin, editor, member), a command palette, email
digests, and an in-app help section. All data is stored in Postgres.

> Ledgerline runs on fictional data. All accounts, APIs, vendors, usage, and
> people are generated by the seed script.

## Public demo

The site opens on a landing page with interactive product snippets.

1. Fill in the form on the landing page. Submitting it opens the demo.
2. On the Ledgerline login page, click **Enter as Admin** (full access) or
   **Enter as Member** (read-only view).

Deployment steps are in [DEPLOY.md](DEPLOY.md).

The demo database is reset every night, so changes you make are removed the
next day. Integrations are simulated (`MOCK_INTEGRATIONS=true`), and no mail
credentials are set, so the demo sends no email.

## Run locally

Requirements: Node.js 20.6 or later. Docker is not required.

```bash
npm install
cp .env.local.example .env.local
npm run dev
```

`npm run dev` does these steps:

1. Starts an embedded Postgres server on port 54329 (data in `./.pgdata`). Set
   `LOCAL_PG_PORT` to use a different port.
2. If the database is empty, applies `migrations/0001_baseline.sql` and seeds
   fictional data.
3. Starts Next.js on port 3000.

Open the printed URL and click **Enter as Admin** or **Enter as Member**.

- **Admin** (Maya Sharma): pricing, margin, invoicing, users, and settings.
- **Member** (Rohan Mehta): the read-only view.

To regenerate the data, run `npm run seed`.

If `embedded-postgres` cannot download a Postgres binary for your platform,
set `DATABASE_URL` to any Postgres 14 or later database and run
`npx tsx scripts/db-setup.ts` and `npx tsx scripts/seed-mock.ts`.

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Start embedded Postgres, set up and seed the database if it is empty, start the Next.js dev server |
| `npm run seed` | Reseed the fictional data (`npm run reseed` is the same command) |
| `npm run setup` | Apply the schema and seed, then exit |
| `npm run db:setup` | Apply the schema only, then exit |
| `npm run migrate` | Apply pending migrations, then exit |
| `npm run build` | Build the app against the embedded database |
| `npm run start` | Start the built app on port 3000 |
| `npm run vendor-sync` | Run the simulated vendor-side usage pull (the database must be running) |
| `npm run check:cmd` | Run the command palette query checks (no database) |
| `npx tsc --noEmit` | Type-check the project |

## Project layout

| Path | Contents |
|---|---|
| `src/app` | Next.js App Router pages and API routes (`src/app/api`), including the cron routes in `src/app/api/cron` |
| `src/components` | React components |
| `src/lib` | Data access (`src/lib/repos`), money math, pricing, sync, alerts, emails, and help content |

| `src/middleware.ts` | Redirects signed-out browsers to `/login` |

| `scripts` | Local runner (`local.ts`), schema setup, seed data, and checks |
| `public` | Fonts, brand assets, and help screenshots |

## Stack

- Next.js 14 (App Router), React 18, TypeScript
- Postgres through postgres.js; embedded-postgres for local development
- NextAuth v5 with a demo Credentials provider
- Tailwind CSS, Recharts, Framer Motion, cmdk, Radix UI
- @react-pdf/renderer for invoice PDFs, KaTeX for the help math page
- decimal.js-light for money, Zod for input validation

The data layer is a set of typed repository modules over SQL. One view,
`usage_daily_with_revenue`, prices each usage row with the account price,
vendor cost, bundles, and sandbox rules. Tier and slab pricing is recomputed
over the whole billing period for invoices.

## Integrations in the demo

With `MOCK_INTEGRATIONS=true`, the usage sync and the vendor-side usage pull do
not call external services. **Refresh now** and **Backfill** on Data & sync
generate usage locally from recent history. In the demo, **Refresh now** also
runs the vendor-side pull and the alert check.

The cron routes under `/api/cron` need a bearer token that matches
`CRON_SECRET`. You can call them by hand. Add `?dry=1` to a digest route to
preview its email as HTML without sending it:

```bash
curl -H "Authorization: Bearer local-dev-cron-secret" \
  "http://localhost:3000/api/cron/product-update-weekly?dry=1"
```
